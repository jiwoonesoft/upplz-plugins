# MCP 원자 도구 계약 (요약)

스킬(오케스트레이터)과 `/upplz:init` 커맨드가 호출하는 upplz MCP 도구(21개). 상세 파라미터는 도구 자체 설명 참조. 사전조건 게이트는 도구가 최종 방어한다.

**격리 단위는 프로젝트다.** API 키 하나가 프로젝트 하나를 가리키고, 식별자·인증서 저장소·프로젝트 비밀번호·Bundle ID·빌드는 모두 그 프로젝트 소유다.

**역할은 둘이다** — `owner`(공유 자산을 만들고 바꾼다) / `collaborator`(협업자 — 빌드·업로드·테스터·스토어 메타데이터 전부). 게이트는 하나뿐이다:

- **owner 전용 4종**(`requireOwner` → `OWNER_ONLY`): `register_ios_credentials`·`register_android_credentials`·`setup_match_repo`·`setup_android_keystore`. 넷 다 **공유 자산을 만들거나 바꾸는** 도구다.
- 나머지 17개는 활성 멤버 누구나 호출한다(`register_bundle_id`·`add_provisioning_profile`·`start_build`·`upload_to_store`·`add_testers`·메타데이터 도구 포함).

**자격이 사는 곳과 전달되는 것**:

- 파일 자산은 전부 **인증서 저장소**(owner 소유 private GitHub, 프로젝트 시크릿 `ios/match-repo-url`)에 있다 — match 인증서·프로파일, `android/<packageName>.keystore`, `upplz/ios/AuthKey.p8.enc`(Apple 팀 키), `upplz/android/service-account.json.enc`(Play Service Account). `.enc` 는 `openssl enc -aes-256-cbc -pbkdf2 -iter 200000` 으로 암호화돼 있다.
- **응답에 실리는 비밀값은 `env.MATCH_PASSWORD`(프로젝트 비밀번호) 하나**다. 스크립트를 돌려주는 모든 도구가 이 값을 싣고 `audit_logs` 에 `matchPasswordDelivered` 를 남긴다. 응답에 `requiredEnv` 가 있으면 언제나 `["MATCH_PASSWORD"]` 다. Key ID·Issuer ID·Team ID 는 비밀이 아니라 스크립트 본문에 리터럴로 들어간다.
- 프로젝트 비밀번호가 저장돼 있지 않으면 스크립트 도구는 전부 `PRECONDITION_FAILED` 다(저장 경로는 `register_ios_credentials`·`register_android_credentials`·`setup_android_keystore`(Android 전용 첫 셋업) 의 `matchPassword` — 전부 owner 전용. `setup_match_repo` 는 비밀번호를 받지 않는다). **이미 저장돼 있으면 어느 도구도 다른 값을 받지 않는다**(`PRECONDITION_FAILED` — 저장값이 이미 저장소의 파일을 잠갔으므로 바꾸면 전부 풀리지 않는다). `get_setup_status` 의 `apple.matchPasswordStored: true` 면 넘기지 않는다.
- **스크립트 실행 규칙**: `env.MATCH_PASSWORD` 를 export → 스크립트를 **통째로** 실행 → 끝나면 unset. 프롤로그가 `[preflight]`(openssl·비밀번호·저장소 접근) → 임시 디렉토리 + `trap` → shallow clone(`[fetch]`) → 필요한 파일만 복호화(`[decrypt]`, 0600) 순으로 돈다. `[fetch] … 가 없습니다` 는 owner 가 지목된 등록 도구를 실행해야 한다는 뜻이다. `[decrypt]` 는 먼저 응답 `env.MATCH_PASSWORD` 를 그대로 export 했는지 확인하고, 맞으면 owner 가 그 파일의 등록 도구(`.p8` → `register_ios_credentials`, Play SA → `register_android_credentials`)를 다시 실행해야 한다는 뜻이다(같은 저장소를 다른 upplz 프로젝트도 쓰면 재실행 대신 대시보드 '다른 프로젝트에서 복사' 로 비밀번호를 맞춘다 — 응답 `troubleshooting.passwordMismatch` 가 파일 종류별 공용 문장이다).

> **인증서 저장소는 플랫폼 공통이다.** 프로젝트 시크릿 키 이름이 `ios/match-repo-url` 이지만 **Android 도 같은 값을 읽는다** — iOS 의 match 저장소와 Android 의 keystore·SA 저장소는 **같은 private GitHub 저장소 하나**다(`ios/` 접두사는 iOS 가 먼저 생겼다는 역사적 흔적일 뿐이며, 키 이름은 마이그레이션 비용 때문에 바꾸지 않는다). iOS 를 이미 설정한 프로젝트라면 Android 는 저장소 URL 을 다시 넣지 않아도 되고, Android 전용 프로젝트는 `register_android_credentials`/`setup_android_keystore` 의 `matchRepoUrl` 파라미터로 등록한다.

## 온보딩/셋업
- `get_setup_status` — **iOS·Android 첫 배포 셋업 상태 종합 판정(read-only)**. 온보딩 시작·재개 시 **첫 도구 호출**로 쓰고, 셋업 단계 하나를 끝낼 때마다 다시 호출해 `nextStep`으로 분기한다(first-time-setup.md "셋업 완료 판정"). **서버는 Apple·Google 을 조회하지 않는다 — DB 기록(시크릿 존재·audit·빌드)만 본다.** 파라미터: `platform?`(`ios`(기본)|`android` — 최상위 `nextStep`·`nextStepHint`·`setupComplete` 를 어느 블록 것으로 채울지만 고른다. **서버는 프로젝트가 어느 플랫폼인지 추정하지 않는다 — 호출자가 고른다**), `bundleId?`(`register_bundle_id`로 이미 저장된 ID와 다른 ID를 확인할 때만 — 저장 전에는 넘기지 않는다), `packageName?`(Android 패키지명 — **판정에는 참여하지 않고** `nextStepHint` 의 요청문(`setup_android_keystore({ packageName: "com.example.app" })`)에 실제 값을 찍는 데만 쓴다). 응답: `platform` / `team.role`(`owner`|`collaborator`) / `apple{ credentials(Key ID·Issuer ID·Team ID 3종 존재), matchRepoUrl, matchInitialized(setup_match_repo 발급 기록 — 약한 근거), matchPasswordStored(값은 반환하지 않는다) }` / `bundleId`(string|null) / `nextStep` / `nextStepHint`(한국어 한 문장, 사용자에게 그대로 안내) / `setupComplete` / **`ios{ nextStep, nextStepHint, setupComplete }`·`android{ certRepoUrl, keystoreScriptIssued, buildSucceeded, keystorePrepared, serviceAccountStored, nextStep, nextStepHint, setupComplete }` — 두 블록은 항상 함께 온다**. iOS `nextStep`: `register_ios_credentials`|`register_bundle_id`|`setup_match_repo`|`start_build`. Android `nextStep`: `setup_android_keystore`(저장소 URL 부재 또는 keystore 미준비 — `android.certRepoUrl` 로 구분)|`register_android_credentials`|`start_build`. 역할은 판정을 바꾸지 않고 `nextStepHint` 문구만 바꾼다(owner 전용 단계면 "owner 가 해야 한다" 요청형, 저장소를 clone 하는 단계면 비-owner 에게 GitHub collaborator 안내가 붙는다). **확인하지 않는 것(힌트로만)**: ASC 앱 레코드·프로비저닝 프로파일·저장소 안 파일 실존·협업자의 저장소 권한·Play Console 앱 생성. 에러: `{ error: "Unauthorized" }` / `SETUP_STATUS_FAILED`(서버 일시 장애, 재시도).
- `analyze_repository` — 저장소 구조·projectType 분석.
- `register_ios_credentials` — **owner 전용**(`OWNER_ONLY`). Apple 팀 키 등록·교체. 파라미터: `authKeyPath`(**.p8 파일의 절대 경로** — 본문을 읽어 넘기지 않는다. 영문·숫자·공백·`._@/-` 만) / `keyId` / `issuerId` / `teamId` / `matchRepoUrl?`(프로젝트에 아직 없을 때만 — 미입력 시 저장값, 둘 다 없으면 `PRECONDITION_FAILED`. 넘기면 덮어쓴다) / `matchPassword?`(8자 이상 — 프로젝트에 비밀번호가 없으면 **필수**, 있으면 넘기지 않는다 — 다른 값은 거부). 서버는 식별자 3종(+넘긴 URL·새로 정한 비밀번호)을 저장하고, 응답 `script` 가 사용자 맥에서 `.p8` 를 확인(`openssl pkey`)·암호화해 `upplz/ios/AuthKey.p8.enc` 로 push 한다(같은 파일이면 `[done] 변경 없음`). 응답: `stored`(저장된 키 목록) / `replaced`(**저장돼 있던 Key ID 가 이번 값과 다를 때만 true** — 같은 키 재등록·기존 프로젝트 이관은 false) / `previousKeyId?`(replaced 일 때 — Revoke 대상) / `certRepoPath` / `script` / `env.MATCH_PASSWORD` / `execution` / `troubleshooting{ repoAccessDenied, pushRejected, notAPrivateKey, passwordMismatch }` / `nextStep`. 형식 오류는 `INVALID_INPUT` + `errors`(필드별 안내)이며 **입력값은 응답·로그 어디에도 되돌아오지 않는다**.
- `register_android_credentials` — **owner 전용**(`OWNER_ONLY`). Play Service Account 등록·교체. 파라미터: `serviceAccountPath`(**키 파일의 절대 경로** — 본문을 읽어 넘기지 않는다) / `clientEmail`(`jq -r .client_email <파일>` 또는 `node -e 'console.log(require(process.argv[1]).client_email)' <파일>` 로 뽑은 공개 식별자) / `matchRepoUrl?`(미입력 시 프로젝트의 저장소 URL, 둘 다 없으면 `PRECONDITION_FAILED`) / `matchPassword?`(프로젝트에 없으면 **필수**, 있으면 넘기지 않는다 — 다른 값은 거부). 서버는 `android/service-account-email` 에 `clientEmail` 을 저장하고(이 키의 존재가 "SA 등록됨"), 응답 `script` 가 `node` 로 파일을 확인(`type=service_account`·`client_email` 일치·`private_key`)한 뒤 암호화해 `upplz/android/service-account.json.enc` 로 push 한다. 교체면 옛 `private_key_id` 를 출력한다(Google Cloud 에서 그 키 삭제). 응답: `replaced` / `clientEmail` / `certRepoPath` / `script` / `env.MATCH_PASSWORD` / `nextStep`.
- `register_bundle_id` — 활성 멤버 누구나. 로컬 `fastlane produce --skip_itc` 스크립트 반환(Developer Portal Bundle ID 등록 — 스크립트가 저장소에서 `.p8` 를 풀어 쓴다). **ASC 앱 레코드는 만들지 않는다** — App Store Connect API 가 앱 생성을 지원하지 않아 사용자가 ASC 웹(My Apps → + → New App)에서 직접 만든다(App Manager 이상). 사전 조건: `register_ios_credentials` 완료 + 프로젝트 비밀번호.
- `setup_match_repo` — **owner 전용**(`OWNER_ONLY` — 인증서 발급·`forceNuke` 가 프로젝트 전체의 코드서명 자산을 바꾼다). match 저장소 초기화 + 공용 Distribution 인증서 + 첫 프로파일 로컬 스크립트(파라미터: `matchRepoUrl?`, `forceNuke?`). **비밀번호 파라미터가 없다** — `register_ios_credentials` 가 저장한 값을 `env.MATCH_PASSWORD` 로 싣는다. 사전 조건: `register_ios_credentials`(식별자·프로젝트 비밀번호) + `register_bundle_id`(`ios/bundle-id`). 응답 `matchPassword`는 정책 안내 객체(`policy`/`firstTime`/`existing`)이며 **값은 포함되지 않는다**(값은 `env.MATCH_PASSWORD`). 스크립트는 fastlane 실행 전에 **fastlane 설치·저장소 접근**을 점검하고 clone 뒤 **match 초기화 여부**(match 가 쓰는 브랜치(`MATCH_GIT_BRANCH`, 기본 `master`) 의 `match_version.txt` — 기본 브랜치의 트리가 아니다. GitHub 새 저장소는 기본 브랜치가 `main` 이라 upplz 파일은 `main` 에, match 는 `master` 에 쓴다)로 새 저장소·기존 저장소를 알려 주며, 실패 원인은 응답 `troubleshooting{ fastlaneMissing, repoAccessDenied, passwordMismatch, certLimit }`(`src/lib/ios-match-script.ts` `buildMatchTroubleshooting()`)로 안내한다. match 미초기화 저장소는 최초 초기화로 간주해 계속 진행한다(저장소에는 `register_ios_credentials` 가 넣은 `upplz/ios/AuthKey.p8.enc` 가 이미 있으므로 "비어 있는가" 로는 판정하지 않는다).
- `add_provisioning_profile` — 활성 멤버 누구나. 다른 Bundle ID(익스텐션·두 번째 앱)의 프로비저닝 프로파일을 저장소에 추가하는 로컬 스크립트(`bundleId?` — 미지정 시 `ios/bundle-id`). 인증서는 재사용한다. match 는 멱등이라 같은 ID 로 다시 실행해도 안전하다. **match 미초기화 저장소(match 브랜치 — 기본 `master` — 에 `match_version.txt` 없음)면 `[match]` 오류(exit 1)로 중단**한다(owner 가 `setup_match_repo` 를 아직 안 했다는 뜻 — 팀 멤버가 read-write match 로 새 Distribution 인증서를 만들어 버리는 것을 방지). ASC 앱 레코드는 필요 없다. 실패 원인은 같은 `troubleshooting` 객체로 안내한다.
- `setup_project` — 로컬 스캐폴드(Capacitor 등) + 로컬 커밋. `platform`(`ios`(기본)|`android`) 파라미터로 대상 선택. `bundleId`는 항상 필수(zod 레벨). platform=ios(기본)는 `iconUrl` 파라미터로 초기 아이콘 지정 가능. platform=android는 `packageName`(미지정 시 `bundleId` 값을 패키지명으로 대체)으로 Capacitor Android 플랫폼을 추가/동기화한다(`android/` 디렉토리가 없어 `start_build`가 실패하는 경우 먼저 이 도구로 추가).
- `setup_android_keystore` — **owner 전용**(`OWNER_ONLY` — keystore 는 인증서 저장소에 사는 **프로젝트 공유 자산**이고, 다른 사람이 먼저 push 하면 Play 업로드 키와 어긋난다). Android 서명용 keystore 를 **인증서 저장소**에 준비하는 로컬 스크립트 반환(서버는 keystore 파일을 받지도 보관하지도 않는다). 파라미터: `packageName` 필수, `matchRepoUrl?`(미입력 시 프로젝트의 저장소 URL, 없으면 `PRECONDITION_FAILED`), `matchPassword?`(8자 이상 — 프로젝트 비밀번호가 아직 없을 때만, 곧 **Android 전용 첫 셋업**. keystore 비밀번호도 같은 값이다. 없이 부르면 `PRECONDITION_FAILED`, 저장값과 다르면 거부). URL·비밀번호는 모든 검증을 통과한 뒤에만 저장된다 — 이 도구 하나로 Android 전용 프로젝트가 Play Service Account 없이 첫 AAB 까지 간다. 스크립트는 **3분기** — ① 저장소에 `android/<packageName>.keystore` 가 있으면 프로젝트 비밀번호로 열어 보고 재사용(열리지 않으면 `[error]` 와 함께 `keytool -storepasswd` 명령을 출력하고 push 없이 exit 1) ② 이 머신에 옛 keystore 가 있으면 저장소로 **이관**해 push ③ 둘 다 없으면 Docker(`web-game-android`)의 keytool 로 생성해 push. **어느 경우에도 저장소의 기존 파일을 덮어쓰지 않는다** — Play 앱 서명을 쓰는 앱에서 이 keystore 는 **업로드 키**라 Play Console 의 업로드 키 재설정으로 **교체할 수 있지만** 그동안 업로드가 막히고, **Play 앱 서명을 쓰지 않는 옛 앱**이라면 곧 앱 서명 키라 **교체 불가**다. 응답: `certRepoUrl` / `keystorePath`(저장소 내 상대 경로) / `script` / `env.MATCH_PASSWORD` / `serviceAccountStored` / `nextStep`(SA 미등록이면 `register_android_credentials` 안내) / `troubleshooting{ repoAccessDenied, pushRejected, keystoreDiverged, passwordMismatch }`.

## 빌드/업로드
- `start_build` — 활성 멤버 누구나. `platform`(`ios`(기본)|`android`) 파라미터. 프로젝트 비밀번호가 없으면 **두 플랫폼 모두** `PRECONDITION_FAILED` — iOS 는 "owner 가 `register_ios_credentials` 의 matchPassword 로 저장해야 합니다"(식별자·저장소 URL·match 초기화가 전부 그 도구 선행이라 하나만 가리킨다), Android 는 "owner 가 `setup_android_keystore({ packageName, matchPassword })` 로 저장해야 합니다"(SA·Apple 키 없이 정할 수 있는 길이다). **iOS**: preflightScript·buildScript + `env.MATCH_PASSWORD` 반환, `.upplz/App.ipa` 생성. **응답에 Apple API 키(.p8)가 들어 있지 않다** — buildScript 의 match 는 `--readonly` 라 저장소의 인증서·프로파일만 받는다. 서버는 프로파일 존재를 확인하지 않는다(없으면 match 가 실패로 드러낸다 → `add_provisioning_profile`). 게이트: `PRECONDITION_FAILED`(식별자·저장소 URL·비밀번호) / `BUNDLE_ID_REQUIRED` / `MARKETING_VERSION_REQUIRED` / `BUILD_IN_PROGRESS`. repoUrl 필수. projectType 미지정 시 직전 빌드 값→web-capacitor 기본(native 첫 빌드는 반드시 명시, 모호 시 scheme/xcodeProjectPath). **Android**: preflightScript(Docker·이미지·openssl·**인증서 저장소 접근**·비밀번호 점검) + buildScript(인증서 저장소 shallow clone → keystore 마운트 → Docker+gradle bundleRelease → 임시 디렉토리 삭제) 반환, `.upplz/app-release.aab` 생성. keystore 비밀번호는 같은 `env.MATCH_PASSWORD` 다. 인증서 저장소 URL 이 없으면 `PRECONDITION_FAILED`("owner 가 `setup_android_keystore({ packageName, matchRepoUrl, matchPassword })` 로 저장소 URL·프로젝트 비밀번호를 정하고 keystore 를 준비해야 합니다" — Android 전용 프로젝트는 이 한 번으로 Play Service Account 없이 첫 AAB 까지 간다. 등록 도구 둘로 보내지 않는 이유: Apple·Play 키 파일이 있어야 하고 불러도 keystore 가 없어 빌드가 다시 멈춘다). 저장소에 keystore 가 없으면 buildScript 가 "owner 가 `setup_android_keystore` 를 실행해야 한다"며 멈춘다 — 그 문구를 그대로 전달한다. 협업자 세션이면 응답 `notes` 에 저장소 collaborator 권한 안내가 붙는다. gradle 위치(`android/` 하위 우선, `native-android`는 저장소 루트 폴백)와 빌드 파일(`app/build.gradle` 우선, `.kts` 폴백)은 buildScript가 자동 탐지하며, 버전 주입은 Groovy·Kotlin DSL 대입 형식을 지원(변수 대입 스타일은 명시적 에러). `packageName`(미지정 시 `bundleId` 값으로 대체, 둘 다 없으면 PACKAGE_NAME_REQUIRED) 필수. `projectType`은 `web-capacitor`|`native-android`만 지원(그 외 UNSUPPORTED_PROJECT_TYPE). `versionCode` 는 Android 전용(iOS 에 넘기면 명시적 에러).
- `get_build_status` — 빌드 상태 조회.
- `upload_to_store` — 활성 멤버 누구나. `platform`(`ios`(기본)|`android`) 파라미터. 응답 `env` 는 두 플랫폼 모두 `MATCH_PASSWORD` 하나다. **iOS**: 로컬 pilot 업로드 스크립트(프롤로그가 저장소에서 `.p8` 를 풀어 `api_key.json` 을 만든다). 사전 조건: `register_ios_credentials`(식별자·저장소·비밀번호). 실패 해석은 응답 `appleErrorGuidance`(앱 레코드 없음 등)·`troubleshooting`. VERSION_ALREADY_USED 시 marketingVersion 상향 후 재빌드. **Android**: fastlane supply 스크립트 — 프롤로그가 저장소에서 SA 를 `$WORKDIR/secrets/service-account.json`(0600)으로 풀고 컨테이너에는 `$WORKDIR/secrets` 의 `/secrets:ro` 마운트와 `SUPPLY_JSON_KEY` **경로만** 넘긴다(`docker inspect` 노출 회피 — docker 줄은 윈도 Git Bash 의 경로 변환을 막는 `MSYS_NO_PATHCONV=1`·`cygpath -m` 형태다). SA 미등록(`android/service-account-email` 없음)이면 `PRECONDITION_FAILED`("owner가 `register_android_credentials`로 등록해야 합니다"). buildId가 android 빌드가 아니면 PLATFORM_MISMATCH. 빌드 metadata에 packageName이 없고 파라미터도 없으면 PACKAGE_NAME_REQUIRED. `aabPath`(기본 `./.upplz/app-release.aab`)·`track`(기본 internal) 선택 파라미터. 응답의 `playErrorGuidance`(PLAY_APP_NOT_FOUND/SA_PERMISSION_DENIED/PACKAGE_NAME_MISMATCH/VERSION_CODE_ALREADY_USED)는 fastlane 실행 결과 해석용 가이드 텍스트다 — **PLAY_APP_NOT_FOUND**: Play 정책상 최초 1회는 Play Console 웹에서 AAB를 수동 업로드해 앱을 생성해야 이후 이 도구가 동작한다.
- `report_build_result` — 빌드/업로드 결과 DB 기록 + 쇼케이스. 플랫폼은 빌드가 기록된 `platform`(`start_build`에서 확정)을 항상 따른다 — `showcase.platform`은 하위호환용 파라미터일 뿐 판정에 쓰이지 않는다(아이콘이 있을 때만 수집, 대표 스크린샷은 선택). **iOS이고 status가 failed가 아니면 스토어에 공개된 앱일 때 서버가 iTunes Lookup으로 appName/storeUrl/iconUrl/screenshotUrl을 자동 보강**한다(에이전트 제공 값이 우선이며, 빈 필드만 채운다). android는 미지원(직접 제공 필요).

## 메타데이터/에셋
- `pull_ios_metadata` / `apply_ios_metadata` — 활성 멤버 누구나. 스토어 메타데이터 pull/apply(로컬 fastlane deliver). scope=listing|screenshots|all. Key ID·Issuer ID·Team ID 는 등록값을 서버가 스크립트에 넣는다(파라미터로 받지 않는다 — 저장소의 `.p8` 와 다른 Key ID 는 401 이 날 뿐이다). `.p8` 는 프롤로그가 저장소에서 풀어 쓴다. 응답 `env` 는 `MATCH_PASSWORD` 하나. 응답의 `securityNote`·`troubleshooting.keyFileNotFound` 문구를 **그대로 전달**한다. 메타데이터 수정은 팀 키의 ASC 역할이 **App Manager 이상**이어야 한다(Developer 로는 403).
- `pull_android_metadata` / `apply_android_metadata` — 활성 멤버 누구나. Android 스토어 리스팅(제목/설명/릴리스노트/아이콘/스크린샷/피처 그래픽) pull/apply(로컬 fastlane supply, `web-game-android` Docker 컨테이너). AAB 바이너리는 다루지 않는다. `packageName` 필수, `metadataPath`(기본 `android/fastlane/metadata/android`) 선택. `apply_android_metadata`의 `scope`(listing|changelog|images|all, 기본 all)로 범위 선택. **Play Service Account 는 프롤로그가 인증서 저장소에서 풀어 쓴다** — `env.MATCH_PASSWORD` 를 export 한 뒤 응답의 command 를 **통째로** 실행한다(Appfile 은 `SUPPLY_JSON_KEY`, 이미지 스크립트는 `GOOGLE_APPLICATION_CREDENTIALS` 를 읽는다). 미등록이면 `PRECONDITION_FAILED`("owner가 `register_android_credentials`로 등록해야 합니다"). 최초 AAB가 아직 수동 업로드되지 않은 앱은 `pull`/`apply` 모두 실패한다(troubleshooting 참고).
- `generate_ios_screenshots` — 웹앱(web-capacitor) 스크린샷 생성(Playwright) + frameit(프레임·제목).
- `generate_native_screenshots` — 네이티브 앱(native-ios/flutter/react-native) 스크린샷 생성(xcrun simctl 시뮬레이터, 사용자가 화면 이동 후 Enter로 캡처).
- `generate_app_icon` — 1024 마스터 아이콘 생성 로컬 스크립트(파생 사이즈는 Xcode가 빌드 시 자동 생성). `iconSource`는 이미지(URL/PNG) 또는 **SVG**(rsvg-convert 우선→magick 래스터화, ImageMagick은 항상 필요) — 소스 제공 또는 Claude가 설계한 SVG 생성 택일. optional `appiconsetPath` — 자동 감지(`find .`)가 실패할 때 AppIcon.appiconset 경로를 직접 지정. 크레덴셜 무관, 변경 후 재빌드 필요.

## 테스터
- `add_testers` — 활성 멤버 누구나(iOS 전용 — Android 에는 TestFlight 테스터 개념이 없다). 로컬 `fastlane pilot` 테스터 추가 스크립트(프롤로그가 저장소에서 `.p8` 를 풀어 쓴다) + `env.MATCH_PASSWORD`. 사전 조건: `report_build_result(status=uploaded)` 로 보고된 빌드. 테스터 관리는 팀 키의 ASC 역할이 **App Manager 이상**이어야 한다(Developer 로는 403). 그룹 hasAccessToAllBuilds=true면 기존 테스터에게 새 빌드 자동 노출.
